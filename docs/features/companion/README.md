# Local companion

The static website and desktop use the same renderer. The optional desktop process owns native dialogs, OS-encrypted local records, isolated Git history and the loopback Ollama adapter. Browser features stay in the website. The companion module registers `companion` through the shared feature registry.

## Security boundaries

The window has a sandboxed preload, context isolation and no renderer Node access. IPC accepts only operations listed in `desktop/security.cjs` from the exact packaged main-frame app://jackson/index.html origin. Requests have a 1 MiB bound. File import/export is selected through native dialogs, and editor access accepts opaque handles created by those dialogs rather than arbitrary paths. External navigation accepts HTTPS and mail addresses without embedded credentials. Browser permission prompts are rejected.

The optional Manifest V3 extension runs only below `https://ding-ding-projects.github.io/jackson-chung/`. The native broker independently checks that scope, a short-lived request timestamp, unique request identifier and explicitly granted pairing capability. Pairing values stay in browser session storage and desktop process memory. Revoking desktop grants invalidates every value and cancels active model tasks. The bridge accepts no shell command or arbitrary filesystem operation. Pairing is not an authentication mechanism against another process already controlling the user's account.

## Packaging and installation

Ship all `desktop/*.cjs` with `dist/`. Include a complete trusted Git distribution at `resources/tools/git/`, including `cmd/git.exe` and its dependent runtime files. Source and packaged execution do not claim PATH Git is bundled. The secure standard app://jackson/ protocol serves only the resolved dist tree and starts the shared renderer at #tools. It supports local fetch and workers without granting Node access. Missing Git produces a recovery state while encrypted saves continue. The desktop/native-host-launcher/ project supplies a self-contained .NET 8 native-host executable launcher. Publish it beside JacksonChung.exe and unpack desktop/native-host.cjs plus its bridge/security modules under resources/app.asar.unpacked/desktop/. The launcher runs only that installed executable and fixed script, sets ELECTRON_RUN_AS_NODE in the child environment, forwards binary standard input/output and discards diagnostic output. Browser-provided arguments are never forwarded. Squirrel install/update events invoke the launcher registration route to write a per-user native messaging manifest named `org.jacksonchung.companion` for Chrome, Edge and Chromium. Uninstall removes only registry entries pointing at that installation. The checked-in public key establishes the stable extension identity `nmehnkibdepbhmfggkofdpngpklinahg`; packaging derives and verifies it again. The manifest's allowed extension origin must be that exact identity. Source extension files alone do not establish installed native integration.

The packaging scripts use a fresh uniquely owned staging/output directory per run, verify the official MinGit-2.51.0-64-bit.zip release asset against the pinned size and SHA-256 before extraction, validate archive paths and bundled git.exe version, publish the self-contained native launcher, assert unpacked host modules and expected Squirrel outputs, then copy the outputs to release/. Existing trusted .NET SDK 8, 9 or 10 is reused to target net8.0. If absent, packaging downloads official pinned portable SDK 8.0.414 after verifying the official release metadata and pinned SHA-512, extracts it under the task cache and reads it back. Missing or invalid official bytes remain explicit blockers. Only the official electron-winstaller select-7z-arch install script is run when its selected 7-Zip payload is absent. Public extension metadata is packaged; private signing material is never read by the packaging scripts. Squirrel install/update/uninstall events create or remove shortcuts through the adjacent Update.exe and propagate native-host registration failures. The application never initiates a computer restart. Automatic updates stay disabled unless packaging supplies `desktop/verified-update.json` with verified source, immutable tag, HTTPS project feed, and both normal-release flags false. There is no guessed update endpoint or success claim before real release metadata exists.

## Records and local history

OS encryption must be available before writing records. The private record file is atomically replaced. Complete encrypted snapshots are recorded in a separate Git directory under the application's own data directory, never the user's source folder. No plaintext snapshot enters history. Restoring a revision creates a new revision. A history write failure does not discard an otherwise successful encrypted save, and the result tells the caller to repair the bundle. Current history UI lists the most recent 100 revisions and supports append-only restore. History browsing and restoring require a local password (set on first unlock), with a five-minute session and explicit lock control. Date/action/regex filtering, diff, labeling, retention, pruning and full history export are not yet implemented, so full history acceptance is pending.

## Ollama

Requests target only `http://127.0.0.1:11434/api/` with fixed tags/ps/chat/pull routes and rejected redirects. Chat and pull responses are streamed as bounded task chunks with cancellation, a 15-minute timeout, an 8 MiB output bound, eight concurrent-task limit and one-minute completed-task retention. Batch downloads run sequentially with exact model identifiers. The UI never guesses hardware or available memory. Missing Ollama provides the official installation link. The Model Store enumerates every model and exact variant linked by the official https://ollama.com/library and per-model /tags HTML sources, following page/cursor/offset pagination. It records each page URL, SHA-256 and available ETag, aggregate immutable response identity, page count, refresh time and last successful refresh. Enumeration uses four workers with 2048-page, 256 MiB aggregate and 4 MiB/page limits; any limit, parser change, unavailable page or cancellation leaves refresh incomplete and retains the previous verified cache. Cache access is paginated in 100-row IPC responses. Locally installed tags absent from the current official catalog are retained in the shared list. Completeness means complete enumeration of the published source responses, not a claim about unpublished models. Installed and running models use the official tags and ps endpoints. A live source-only acquisition at 2026-10-10T06:56:11.413Z returned 245 model families, 7439 variants and 246 pages with aggregate response identity 89c27a119b62223d2dd1e61b3774987d511dd34248b9233aa407fe409794d8f4. This is network acquisition evidence, not installed runtime or UI acceptance. Metadata responses are limited to 1 MiB and 4096 models, with bounded names and validated nonnegative numeric metadata.

Installed Squirrel lifecycle, native host registration, bundled Git resolution, OS encryption behavior, native dialogs, streaming against an actual Ollama service, extension pairing/revocation and the viewport/language/theme/scale capture matrix require genuine installed runtime evidence. The extension popup is a minimal setup control, and does not yet satisfy the full shared interface contract.

## Model hardware evidence and remaining store acceptance

Selected-tag inspection obtains exact layer bytes from the allowlisted official registry manifest, with a bounded validated schema and response hash. RAM and architecture are measured through the operating-system API; GPU identity is exposed only when Electron supplies it. Usable VRAM, Ollama backend/driver support and the running service's actual storage destination remain unavailable through the current verified adapter. They are never filled from model names, nominal adapter memory or assumed zero values. Configurable context overhead is explicitly an assumption. Fit returns Runs well, Runs with limits, Unlikely or Unknown with its timestamp and complete evidence; insufficient measured RAM can be Unlikely, while missing required facts remain Unknown. Recommendations do not promise successful execution.

The current store supports plain-text search, bounded 250 ms worker regex search, family/installed/fit filters, tag or inspected-size sorting, page navigation, scoped bulk selection/inversion, a reviewable local-pull cart and the existing real cancellable sequential pull workflow. Each actual companion search now opens the shared full anchored regex workbench. Running/capability/quantization/size filters, complete published per-variant parameter/context metadata, durable cart/item reconciliation, configurable parallel pulls, accurate aggregate transfer/storage estimates, complete offline troubleshooting, snapshot/rollback launch profiles and installed capture acceptance remain incomplete. Their absence is not converted to success by source enumeration or fit unit tests.

## Editable companion drafts

JSON record edits and model input drafts participate in the shared tab draft registry. JSON becomes clean only after a real native `store.write` acknowledgement with `saved: true`. Failed, invalid or missing acknowledgements retain the edited text. Concurrent edits during a successful save remain dirty against the exact acknowledged snapshot. Loading or importing cannot silently replace a dirty draft. Discard restores only the transient JSON editor to its last acknowledged baseline, without writing or restoring the encrypted store.

Model identifier, message and manual pull-list inputs are transient and have no persistence adapter. Their provider therefore offers discard, not a fictitious save. Discard clears those inputs only; it does not cancel tasks or change installed models. Active actions, in-flight requests, running tasks and record saves veto disposal through the shared API. Provider registrations are removed on component teardown. Native operating-system close behavior and the full rendered tab-close interaction require separate integration/runtime acceptance.

The companion Close action resolves the shared draft decision first, rechecks unrelated busy work, then invokes the native close operation outside its own action/request counters. This prevents the initiating close from vetoing its own trusted close-request handshake when that event arrives before the invocation response. All other operation counters still block disposal. Failed or cancelled requests leave the workspace available, and a failed transport can be retried. The ordered fixture covers the early-event case; it does not establish the actual operating-system IPC ordering or installed close acceptance.

## Companion search and regex workbench

Three useful fields have separate anchored shared workbenches: official catalog exact variants; installed model choices that fill the exact model identifier; and local revision labels, dates and IDs. Each owns literal-default query, pattern, flags, mode, validation and an independently cancelled worker. Field IDs include the owning tab identity, so snippet controls and applied history remain scoped to that field. Editing either the search or its workbench synchronizes the same state; Apply uses the actual selected flags. Global and sticky expressions reset lastIndex for every candidate.

Search filtering runs in a dedicated worker with a 250 ms deadline, 2048-character query/pattern bounds, 100000-value bound and 16 MiB aggregate text bound. Worker failure or timeout produces a local inline status and no false matches. Workers terminate on field replacement or component teardown. Results contain indices only, never match samples or captures. No JSON snapshot or native private record payload is copied into the builder. Revision filtering covers only the loaded history labels, dates and IDs, not encrypted snapshot contents.

The shared workbench provides its existing construction, capability matrix, explanation, capture/replacement preview, expected-outcome cases, explicit snippet import/export and performance diagnostics. Samples, cases and captures retain that component's transient-only boundary and are not placed in companion exports, record history or logs. ECMAScript engine version and step/backtracking tracing are explicitly unavailable where the engine does not expose them. Source tests prove independent fields, real flag semantics, missing-field detection, index-only outputs and actual worker termination; built layout, keyboard/touch interaction and installed acceptance remain unverified in this source unit.
