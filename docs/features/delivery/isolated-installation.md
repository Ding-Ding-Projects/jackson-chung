# Isolated verification installation

`build-installer.bat /s --verification` produces a genuine Squirrel.Windows package with the separate package ID `JacksonChungVerification`. Its real per-user installation destination is `%LOCALAPPDATA%\JacksonChungVerification`; no environment-variable redirection is used. Production keeps `JacksonChung` and its ordinary installer output unchanged. The verification installer stays in the private build-output area.

The embedded, strictly validated verification manifest selects separate application and Chromium session data below the operating system's actual application-data directory, named `JacksonChungVerification`. This mode skips shortcut creation and browser native-host registration, does not open the production named-pipe broker, and disables the production updater. Local native operations still use the real packaged implementation. This deliberately limited installation can establish packaged launch and shared UI behavior, but cannot prove production browser registration, production shortcut lifecycle or updater behavior.

Before installing, independently resolve and record both actual install and profile destinations, require both to be absent, and check the production destination without changing it. Launch only through a named hidden desktop with exact installer identity. Verify installed bytes and source through independent inspection before launch. Teardown must stop only verified owned processes and remove only the declared verification installation/profile after preserving evidence. Never overwrite an existing destination or change `LOCALAPPDATA` to simulate isolation.

Focused tests prove default-path preservation, real separate user/session directories, and malformed manifest rejection before profile creation. Actual verification installation, installed UI and uninstall remain pending until their real receipts exist. This mode is not a disposable operating-system user or VM, and no such stronger isolation is claimed.
